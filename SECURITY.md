# Security Policy

## 🛡️ Project Security Statement

This repository is dedicated to **educational cybersecurity content** focused on web application vulnerability assessment and penetration testing (VAPT). Security and responsible disclosure are at the core of our mission.

| Version | Support Status |

| Archived versions | ❌ No longer supported |

We continuously update content to reflect current security best practices and vulnerability trends.

## 🚨 Reporting Security Vulnerabilities

### In This Repository

If you discover a security vulnerability in **this repository itself** (not the educational content about vulnerabilities), please report it responsibly:

#### Preferred Method: GitHub Security Advisories

1. Go to the **Security** tab of this repository
2. Click **"Report a vulnerability"**
3. Fill in the advisory form with:
   - Clear description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if known)

#### Alternative Contact Methods

- **GitHub Issues**: Only for non-sensitive security concerns
- **Discussions**: For security questions or clarifications

**Please DO NOT**:
- ❌ Open public issues for serious security vulnerabilities
- ❌ Disclose vulnerabilities publicly before they are fixed
- ❌ Share exploit code publicly without giving time to fix

### Responsible Disclosure Timeline

We follow industry-standard responsible disclosure practices:

1. **Day 0**: Vulnerability reported privately
2. **Within 48 hours**: Acknowledgment of receipt
3. **Within 7 days**: Initial assessment and triage
4. **Within 30 days**: Fix developed and tested (for confirmed vulnerabilities)
5. **Within 90 days**: Public disclosure (coordinated with reporter)

We appreciate security researchers who:
- Report vulnerabilities privately first
- Allow reasonable time for fixes
- Provide clear, detailed reports
- Act in good faith

## 🔒 Content Security Guidelines

### Educational Material Standards

All security content in this repository must:

- **Use sanitized examples** - Never real credentials or production data
- **Emphasize legal boundaries** - Include ethical disclaimers
- **Promote responsible disclosure** - Follow industry best practices
- **Avoid weaponization** - Educational purpose only
- **Include mitigations** - Always provide defense recommendations

### Prohibited Content

This repository will **never** contain:

- ❌ Live exploits targeting real systems
- ❌ Real credentials, API keys, or tokens
- ❌ Personally identifiable information (PII)
- ❌ Production system details or IP addresses
- ❌ Unreported zero-day vulnerabilities
- ❌ Malware or malicious code
- ❌ Tools designed solely for illegal purposes

## ⚖️ Legal and Ethical Framework

### Our Commitment

This repository is committed to:

1. **Legal Compliance**: All content complies with applicable laws
2. **Ethical Standards**: Promotes responsible security practices
3. **Educational Focus**: Designed for learning and authorized testing
4. **Community Safety**: Protects users from malicious content

### User Responsibilities

By using this repository, you agree to:

- **Only test systems you own** or have explicit written permission to test
- **Follow all applicable laws** in your jurisdiction
- **Use knowledge responsibly** for defensive security purposes
- **Respect responsible disclosure** practices
- **Never conduct unauthorized testing** against third-party systems

### Violation Consequences

**Unauthorized use of techniques from this repository may result in**:

- Criminal prosecution under laws such as:
  - Computer Fraud and Abuse Act (CFAA) - USA
  - Computer Misuse Act - UK
  - Similar legislation worldwide
- Civil liability and lawsuits
- Loss of professional credentials
- Permanent legal record

## 📄 Vulnerability Content Guidelines

### When Adding Vulnerability Examples

Contributors must ensure:

1. **Authorization**: Only include examples from:
   - Systems you own
   - Authorized penetration tests (with written permission)
   - Public bug bounty programs (following their rules)
   - Intentionally vulnerable practice labs (DVWA, Juice Shop, etc.)

2. **Sanitization**: Remove or anonymize:
   - Real hostnames and IP addresses
   - Actual credentials and session tokens
   - Personal information
   - Company-specific details

3. **Context**: Always include:
   - Legal authorization information
   - Ethical disclaimers
   - Remediation guidance
   - CVSS scores and impact assessment

4. **Disclosure**: For real vulnerabilities:
   - Ensure proper disclosure to vendor
   - Respect embargo periods
   - Only publish after fix is available
   - Follow CVE assignment process if applicable
